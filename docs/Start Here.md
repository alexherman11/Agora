# Start Here

Agora is a computing environment that its person and JEFF can reshape through
use. Documents, conversations, collections and applications should remain
understandable as their interfaces and behavior evolve.

## Reading the documents

| Document | Purpose |
|---|---|
| [[Constitution]] | The values behind personal control, privacy, recovery and exit. An unratified vision, not a future engineering rulebook. |
| [[Agora Spec]] | The product vision and the structure we have chosen so far. |
| [[Implementation Status]] | What exists, what has been tested, and what remains experimental. |
| [[Runtime Guide]] | Exact operations and package formats implemented by the current runtime. |
| Reference notes | Concepts and design options; only explicitly identified current behavior describes an implemented contract. |
| Essays | Ordinary situations, shared life and long-term possibilities. |
| [[Review Coverage]] | Dated mapping of the September 9 review to the revised documentation. |

The person's direction and evidence from use guide development. When a design
stops helping, revise it. A vision paragraph does not authorize an external
action, establish an implemented guarantee, or require an approval ceremony.
The runtime guide and code describe the present system; contradictions should
be corrected rather than resolved through an ever-growing hierarchy of prose.

## Essays

[[Facets in Everyday Use]], [[Object Use Cases]], [[Rooms]], [[Democracy]] and
[[Ownership]] explore where the environment could go. They are prompts for
useful experiments, not additional conformance requirements.

For contribution practice see [AGENTS.md](../AGENTS.md). Dated implementation
choices belong in [DECISIONS.md](../DECISIONS.md). Exact examples belong beside
their implemented contract. Avoid speculative schemas that look like available
APIs. Keep current documentation self-contained; Git preserves earlier designs.
