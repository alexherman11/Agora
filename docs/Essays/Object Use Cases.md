# Object use cases

**Scenarios to guide experiments, not gates on every implementation.**

| Situation | What the experience should help us understand |
|---|---|
| Write a memo while reading three sources | Stable document identity, citations, drafts and useful editing controls. |
| Reopen work tomorrow | Which content, view preferences and activities persisted, and which resources are unavailable. |
| Show one paper in two places | Independent appearances of one subject, with an understandable editing relationship. |
| Copy a note or playlist item | Whether this is independent content, another use, or a retained reference. |
| Apply a theme, then make an exception | Contributors, resolution, local intent and precise undo. |
| Drag a task into Done | A deliberate domain action, distinguishable from visual rearrangement. |
| Edit while another view changes presentation | Relevant conflict scopes and preservation of unrelated work. |
| Import a source and export a release | Retained bytes, live versus pinned data, audience and dependency scope. |
| Update an external service with a lost response | Observed outcome, idempotency and recovery without blind duplication. |
| Collaborate offline, then reconnect | Competing changes and useful resolution before choosing federation machinery. |

Each scenario can start small and become more realistic. Record what the person
can actually do, what JEFF had to build and what the model or runtime could not
verify. Do not infer complete object-OS behavior from a schema or a passing narrow
test. See [[Native Development]], [[The Web]] and [[Rooms]].
