The short version

A kind is a named way of seeing a thing

A kind is a test that says which things it sees (most often "has these aspects", your definition), the words that work through it, and the defaults it passes on. One thing can be seen many ways at once. Your railing is a railing, a wall and a fence, and it is wooden. Each way of seeing brings its own words.

  • Nouns and adjectives. What a thing is (railing, game) is declared and nests. What it has or is right now (wooden, located, running) is computed and never a parent.
  • is is a promise the world checks. "A railing is a wall" promises railings have what walls have. Structure suggests the promise; one click makes it. A broken promise shows, like a stale link.
  • Words say what they need and reach everything that has it, nearest kind's version first. Words that can't be undone reach a narrower kind only where it said yes.
  • Classifying never adds power. Nesting widens what views show, never what a grant allows.
  • The graph is already half written as text. Typing the aspects that name things (lane=Now) cut the isolated things in your desktop from 81 to 30.
Two pictures, one order

Your two sentences draw the same thing from opposite sides

"A railing is a type of wall" is about things: railings sit inside walls. "If something has less … it kind of sits inside" is about aspects: a wall's aspects sit inside a railing's. More things always means fewer shared aspects. So the order can be computed from what things have, which is one meaning of "more dynamically". recall This is Formal Concept Analysis (Wille, 1982).

  Maybe not always
  
When a word should stop at a kind

  
Seven ways a word shouldn't simply pass down: the same word meaning another act (close is three acts today), the narrower kind's rule forbidding it (a pamphlet's fixed panels), effects that can't be undone, authority, spelling (colour and color), who is looking, and state (a game in a match). The rule set needs no new switch per word, because it reads what the dictionary already holds:

  

    
see, hearAlways carry. Reading is safe, and the kernel's tests already run as the reader.

    
undoable doCarry, nearest kind's version first: the dictionary's ladder over groups, with a twin ladder over kinds.

    
can't undoReach a narrower kind only where it said yes. This guards exactly the PC-acting words.

    
withholdAny kind may withhold a word, with a reason and a way out: "a railing has no door; add gate instead".

    
two disagreeAsk, as your rule says ("ask only when two fit"), and keep the answer on the narrower kind.

    
partlyA write passes through a view only if it can be put back: a comment's quote fits a PDF's text, its heading may not. recall the view-update problem; bidirectional lenses.

  

  

    
Classifying never adds power

    
If anyone could declare "secret note is a window", every grant limited to windows would silently reach secret notes. So a grant names kinds as they stood when it was made, the way stored lines bind their words when saved. Power flows down groups (a leader reaches inner groups) but never down kinds.

  What would change my mind
  
Where this could be wrong

  
    
    
  • Adjectives might be enough. If adjectives and typed aspects give you what you want, nouns needn't nest at all; Go and Rust chose that on purpose, and the probes lean that way. Nesting nouns would then serve finding and explaining only. The Rocket League slice would tell: count what only a noun nesting could do.
    • 
    
  • Promises not kept up. If in a month fewer than half the new kinds say what they are, suggestions (and maybe an embedding model) must carry more.
    • 
    
  • Carried words surprise. If a word that reached a thing only by nesting does the wrong thing more than rarely, carrying becomes opt-in for every do word.
    • 
    
  • One parent each. If almost every kind has one parent, a tree is enough and the lattice is overbuilt.
    • 
    
  • Groups drift apart. If two groups' tasks can't share a board, world kinds should be the default and group kinds the exception.
