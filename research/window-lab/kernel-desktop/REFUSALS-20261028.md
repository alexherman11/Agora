# Refusals and errors reach a log (card dk939)

Claude Code builder, 28 Oct 2026, for JEFF's card dk939 from Alex's ask (Conversation, 27 Oct): every refused line and
error, from any button, word or agent, lands in one readable log. Before this, a failed taskbar close left no record,
and `recent` shows only acts that worked.

## What there is now

    refusals [by=<name|me>] [limit=<n>] [errors] [all]     a reading: the latest refused lines and errors, newest first
    failed why="…" [line="…"] [where=dock]                  a page or agent says what failed outside any line

A row says when, who (and whom a module or widget acted for), the line, and why:

    #12 14:03 ×5 (last 14:07) Alex: wm.windows
          → nothing answers to 'wm.windows' here; …
    #13 14:05 shell-dock for Alex via press: window.close dk431
          → window: only for this desktop's owner
    #14 14:06 guy [died]: (no line)
          → guy stopped by itself: …; started again in 30 s
    #15 14:06 Alex in dock-bar [failed]: (no line)
          → stopped: This part stopped · its renderer exited.

Who sees: a steward (Alex, JEFF) sees everyone's; anyone else sees their own. Lines `help` mentions it on its first
screen, and `refusals` is among the words worth knowing.

## Where the refusals come from

| Source (read) | Before | Now |
| --- | --- | --- |
| `Kernel.run` (every `/do`, `/see`, `/api/do`, widget `agora.do/see`, a module's own line, a rule, `press`) | refusal text returned to the caller, then gone | kept once, by the outermost run on that thread (a press is one row, naming the button's line) |
| a word that raises (a bug) | the door's request dropped; traceback on kdesk's stderr only | kept as `[error]` with the exception and the file:line it last passed |
| painted drop refused before its line ran (`painter.Facade.do`) | receipt only | kept, via press |
| widget broker refusals before any line (`kdesk` `/desk/widget/*`: off or changed, no instance, too quick) | `{ok:false}` to the page | kept, via widget |
| a module that died (`modules.Host.reconcile`) | `why_down`, shown only when a word of it was refused | kept as `[died]` with its last stderr lines |
| a module message that failed in the kernel; a module `happen` refused | 20-line in-memory tail | kept |
| widget-host: a frame that stopped, restarted, a stall it could not recover, a bridge error that was not the kernel's (`#receipt` showed it and forgot) | gone | the page says `failed …` (kd.js `KD.failed`), at most once per 10 s per failure and 60 per page |
| hand-written bar: a native window call that threw (shell.js `Native.call`) | swallowed | said with `failed` |

Not caught (imagined, not tested): a module that answers ok but does nothing. That was the original taskbar close (the
WM in shadow mode after a restart, fixed in 0a309676b): no refusal ever happened, so this log would not have shown it.
The window-module-refused-a-steward half of that incident would now be a row. A page that cannot reach the kernel at all
("the kernel is not answering") cannot report to it.

## Where it lives, and why

Not in the world log. A refusal is the kernel's promise that nothing was written; a world that recorded every refused
poll would grow without being changed, and undo, history and recent would have to step around it. Not visual state
either (Alex, 26 Oct, keeps that local to the screen): it is an event. So it is kept beside the world, in
`<world>/keep/refusals.jsonl`, like sessions and seen-marks: the last 1000 rows, read back when the kernel starts. The
same refusal by the same actor within its last 40 rows is counted on the first (`×N`), not kept again.

What would change my mind: if JEFF or a rule needs to *react* to a refusal (wake on it, count it per card), it should
also be a happening (`refused`, delivered, not recorded) so `hear:` and rules see it. That is one line in
`Refusals._keep`; I left it out because a happening per refused poll would wake hearers for noise.

## Rough spots (source edits and the world-level word that was missing)

- `refusals` (kernel reading, `kernel/refusals.py`, hooks in `kernel.py` `run`, `modules.py`, `painter.py`, kdesk's
  widget door). Missing world word: a reading of what *failed*. `recent` and `history` read the log, and the log holds
  only what was done.
- `failed` (kernel word). Missing world word: a way for a page or agent to say something failed outside any line.
- Pressing a button whose line refuses now says `refused: pressing <label> ran <line>: <why>` (was `refused: <why>`),
  so a receipt, a toast and `refusals` name which line the button ran.
