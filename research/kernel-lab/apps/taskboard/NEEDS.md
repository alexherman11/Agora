# Task board: missing world words

Builder findings, 24 October 2026. No kernel or desktop source was changed.

1. **Carry identity and its fence at the kernel door.** **Ran:** two real pointer drags in hidden Chrome both refuse `task.done needs a thing` / `task.move needs a thing`. `evidence/drag-receipts.json` contains the actual requests, including `$carried` and `observed.carried`. **Read:** `kernel/painter.py`, `Facade.do` translates ids but does not fill `$carried`; `saw_of` reads only top-level observations. The old desk's `deskd.py` fills this blank and checks both participants. The app cannot fill a pointer's identity with a verb note. **Workaround:** card-bound Backlog / Now / Done buttons. Their ordinary painted fences correctly refuse a competing stale move. Carry/drop definitions remain in the lens as a reproducible pending capability, but dragging does not move cards. This is explicitly incomplete, including the requested successful-first/stale-second drag proof.

2. **A permission-filtered record trail as rows.** **Read:** `look <thing>` returns current facts; `rows` adds the thing's current `rev` and real author. Neither returns its record trail. The painter facade makes a World with no events, so `events`, `$touched`, and `$changed` cannot recover the kernel log. **Workaround:** each task move, assignment or note makes a `taskboard-event` with `about=<task>` in the same transaction as the change. History repeats these ordinary things. `evidence/history-records.json` proves each displayed event belongs to the actual task act and carries real authorship and a real record timestamp. Undo of a move removes its event too. This is an app-authored trail, **not the card's raw record trail**: arbitrary `set`, older edits and undo records are not listed in the fold. No invented record ids or timestamps are displayed.

3. **Record timestamps and the current date in the view.** **Ran:** `$today` was left literally in a gesture on the scratch facade; no current date was supplied. **Read:** record `at` exists in the kernel log, but is absent from `look`/`rows` and the facade's thing properties. Imported cards display the import snapshot time, not a claim about when Frontier work began. Locally added cards say `Added here`. History shows real author and action; precise event timestamps are in the scratch evidence, not in the live history fold. **Workaround:** preserve supplied task dates and do not pretend a gesture knows the clock.

4. **Dotted verb declaration; a live dictionary editor.** **Read:** `verb task.add` rejects dotted names. The current scratch kernel supports `verb task-add ...; rename $entry word=task.add`. **Ran:** the live desktop's dictionary lacks `rename`, and `set <word>` refuses changes to a word. The first live attempt made `task-add`, then refused its rename. `install.py` resumes safely and detects this older dictionary, using `task-add`, `task-move`, `task-assign`, `task-done`, `task-note` and rewriting its own lens's calls to match. No shared word was changed. After the desktop dictionary gains `rename`, dotted publication is possible; an existing compatibility lens will still answer through the preserved bare bound names. No restart was attempted.

5. **A composed word's own happening; rule filters.** **Read:** a verb note emits its component words' happenings (`set`, `make`), not `task.done`. A rule listening for `task.done` therefore did not fire. **Workaround:** the one installed rule listens for the existing `claim` happening and adds a history event naming the actual claimer. Every task has one claim seat and a Take button. The rule observes all visible claims, because the current rule contract has no kind filter; events about non-board things are not included in this board's history. The rule is stopped by setting its `off=yes`. This app does not publish a Done announcement in Feed.

These are requests for shared capabilities, not requests to add Task board logic to the host. Native carry/drop admission and a record row source would remove the two substantial workarounds.

6. **Quoted view names survive `window.open`.** **Ran:** `window.open "Task board"` refused `no lens or view called task`. **Read:** the module splits its already parsed words on spaces. **Workaround:** the lens's address is `taskboard`; its displayed heading and window name are `Task board`. The first live multiword lens was renamed with ordinary `set`, and subsequent installation is unchanged.

7. **The desktop host completing its window intent.** **Ran:** `window.open taskboard` admits a window record. `window.list` repeatedly reports that board's `box=null`, `shown=false`, while its six pre-existing windows report shown. The module reports seven desired windows and six opened since start. Closing only this failed board intent and reopening it once produced the same result. **Read:** the host records an HWND and shows its hidden new window on its loaded callback; that callback's completion is not confirmed here. No host restart, direct native show, UI reload, or source fix was attempted while the other builder works there. The live headless painter capture passes, but **the native board is not confirmed visible**. The persisted window intent is ready for the host to reconcile. `install.py` now reports this boundary explicitly instead of equating a successful word receipt with visibility.
