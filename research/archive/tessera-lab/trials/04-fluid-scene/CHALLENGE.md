# Trial 4: break shared geometry assumptions

Three concurrent builders redesign their own existing module. No root integration
edits. All existing scene data/behavior still available. Preserve original trial
03 untouched; current copies are the new artifact. No peer implementation reads
before freeze; negotiate addresses, not pixel contracts, directly.

Studio: replace tiny fixed 190x120 cards with expandable, variable-sized document
cards, legible editing and extensible metadata. Keep card.shell occurrence identity
and card.face/card.tools extension ports. Add at least one new independent window
with a card host (e.g. a reading room). Move cards between arbitrary valid hosts;
replace the hardcoded three-host list using a host registry that YOU introduce and
advertise to the other builders, so all may publish a host as data. Same card remains
editable and connected while its size and host change. Own module only.

Atlas: connect shared cards across windows. Remove the host-local graph assumption.
Use measured endpoint addresses, never +95/+60 constants. Connectors remain attached
through card expansion, window resize/docking, host changes and viewport resize.
The generic language provides paint-only measure expressions, and viewport-space
line primitives. Preserve references or give a clear refusal when a connected card
is deleted. Extend Studio cards through existing ports without assuming fixed size.
Your own window can become a relationship inspector, timeline, or richer graph tool.

Toolkit: rewrite arrangement as generic rules over however many surface records
exist, not three hardcoded dock names/boxes. Provide responsive overview and focused
editing modes plus free movement; all windows reachable at 1600x1000,1000x800 and
600x900. A small viewport may scroll, but must not permanently hide controls.
Use styles, data, views and gestures; no app-specific renderer paths. Include a
legible, deliberate visual redesign for controls and chosen scene styles. Coordinate
new host registry with Studio. Keep explicit style conflict and override capability.

Acceptance: variable-size cards, active cross-window links, independent additional
window, arbitrary-host transfer, responsive recomposition, content persistence,
concurrent disjoint motion, same-field conflict visible, preview-only pointer frames.
The program may be imperfect; silently detached links, lost content, dead controls,
or clipped mandatory operations are failures. Report design friction candidly.
