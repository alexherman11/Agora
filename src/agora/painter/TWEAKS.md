# Component painter: frozen ten-tweak trial

Builder report for Claude's review, 24 October 2026. No git add, commit, push,
branch, checkout or worktree operation was performed.

Small general kernel additions (in `kernel/words.py`, implementation beside it
in `painter/arrangement.py`): **component** (steward review of module bytes),
**look-view** (data-only description/plan), **components** (purpose discovery),
and **help <component>** (typed card/example). `reviewed_code` is reserved against
ordinary writes. The first two words/hash began in the stopped run. Existing
grant/field/undo changes from the pixel-guy builder were preserved; this builder
did not edit `kernel.py`, `kd_guy.py`, `sprite.py`, `kdesk.py` or `lens.js`.

The live opening step also needed a small `kd_window.py` repair: Windows can
refuse background keyboard activation, so the provider must check the result and
report a nonactivating raise honestly. Four fault-path tests cover it. Optional
test-only flags were added to the existing hidden widget browser driver. These
are opening/test seams, not app behaviour added to the old lens painter.

## What was built

**Read:** the live charter, WIDGETS, its JS board, task board v2, SHAPE 17 and the
community guide. **Built:** an independent arrangement compiler and painter,
typed fact bindings, fact-carrying named parts and child slots, guarded word-line
gestures with carried/receiver fences, world styles, owned personal arrangements,
39 first-party catalogue cards and a live component gallery made with the painter.
The task board arranges five components over the existing task/settings facts and
words. A 50-purpose reach map precedes the replacement painter implementation.

Core primitives supply layout/content/input/overlays/focus, numerical spring drag,
Web Animations, streamed invalidation plus a 1.5-second projection reconciliation,
fixed-height DOM windowing and 2D canvas/pixels. Domain backends are not implied
by a component name. Native media playback is blocked by the existing host;
separately granted media verbs can control an OS player.

**Ran:** the hidden A/B board images over the same frozen 25 task rows had mean
absolute RGB channel difference **0.0**, excluding trusted title labels. This is
pixel evidence for this fixture/viewport, not a universal aesthetic or usability
claim. [Side-by-side capture](evidence/board-comparison.png).

## Method and evidence boundary

The source/world freeze is [FREEZE.json](FREEZE.json): 17 source files and one
canonical scratch log snapshot, copied independently for every run. A controlled
record clock creates six-day/four-day lane entries, a recent nonqualifying entry,
and a recent unrelated note. Dates are genuine stamps of that simulated clock,
not writable age hints. The same 25 facts and original record history reach both
boards. A is the component lens; B is the pure JavaScript widget. Tweak state
never stacks.

Every request is unchanged in [requests.json](tweaks/requests.json). Checks were
written before the trial agents. Each agent is a new pinned `codex exec` at
medium effort, with only the guide/docs and ordinary MCP **see/do** tools. Its
principal is an agent for Alex in its scratch world. No previous thread,
filesystem source tool, browser or live-world credential is supplied. Inline
component/widget code remains world data, readable/editable through words when
necessary. The agents could not inspect pixels; the independent checker did.

An initial harness configuration required MCP approval and blocked all writes.
Those attempts were stopped and archived separately as **invalid infrastructure
attempts**, not hypothesis failures. The scored runs explicitly preapprove the
two scratch-door tools. No frozen painter/component handle was repaired during
the twenty scored agents.

Three overly specific checker assumptions were corrected: a chip may say
“Overdue · date”; a functional Waiting lane need not use one storage representation;
and a reading answer may explicitly name a nonqualifying task as an exclusion.
For affected completed runs, the original exact word calls were replayed on a
fresh frozen copy and the **same answer** rechecked. No new agent attempt or
implementation edit was substituted. Original check output, first checker source,
and recheck results are retained. The original failure stays a failure wherever
the corrected check still fails (A2).

Δ lines counts added/removed physical lines across stored world values, including
automatic review/activation/grant metadata. It is not keystrokes or just command
count. Wall time is the original agent+check+functional-proof run; recheck overhead
is separate. “facts” in code runs mostly means those authority/definition facts,
not edits to shared task content. Original agent-only time and per-field diffs
are in each result JSON.

Here **source** means the widget's inline JavaScript world value, not repository
or kernel source. No trial agent edited a repository file. Both kinds of code
travel as world data; changing JavaScript still requires code knowledge/review.

## What the agents struggled with

* **A1:** it wrote `glow="#ef444455"` and said “No code was necessary.” The world
  accepted the style, but the frozen painter requires a six-digit glow colour and
  adds alpha itself. Structural `look-view` did not diagnose that runtime refusal.
* **A2:** it used normal CSS shorthand `padding="4px 8px"`. The frozen guarded
  style subset accepts one measure. The agent's “look-view confirms 3 overdue
  and 2 upcoming chips” was a structural reading, not a successful paint.
* **A6:** correct initials took a cloned/reviewed card plus an arrangement edit.
  The catalogue already has an avatar primitive; the app card hardwires its own
  two-character avatar and does not expose that formatting as a useful handle.
* **A7:** the new component calls `api.rows('taskboard-task')`; that helper takes
  a whole see line (`rows taskboard-task`). It therefore never obtains the task
  readings for the transition. “Structure verified with look-view; animation
  pixels could not be inspected” did not establish a working animation.
* **A8/B8:** the Spanish labels are shared with the other reader. Both miss “for
  me”. A8 edits component code because the lane name combines display and domain
  identity; it never establishes the necessary personal scope.
* **A9:** the agent found a good word-only composition: stamp `snoozed_on=$today`,
  hide while that date is current, and let the same task reappear in its original
  lane on the next UTC day. It reported “only arrangement changes.” The checker
  advances both the kernel clock and page clock and checks identity preservation.
* Several agents first wrote literal backslash-n sequences into multiline lens
  or module source, then corrected them. Transport/literal rules remain friction.
* `look-view` currently returns the renderer plan too, repeating environments and
  code. It is much heavier than the compact reading an agent usually needs.

## Verdict

**Ran:** A passes **6/10**, B **9/10**. Four of the nine changing A requests pass
without component/source code (personal Done hiding, compact cards, Waiting,
snooze); initials passes with code. Its reading question passes. Every changing
B request goes into widget source, even when the resulting UI works.

The arrangement hypothesis earns a narrower result: ordinary world edits can
make several meaningful changes while preserving the board's visual quality.
This freeze does **not** show that the current component handles cover routine
presentation work generally. Missing/poor handles include avatar formatting,
separate display labels/domain values, personal scope that agents reliably use,
and declarative event-to-motion triggers. Style validation must be discoverable
before paint. The five app components still contain application-specific choices;
the primitives alone do not make those choices editable.

Both boards answer the reading question correctly. That legibility comes from
the shared facts/words; it is not a property exclusive to lens syntax. The
independent painter description adds structure, but its current renderer-plan
payload is too large. Because each edit starts with unmounted fresh pages, this
trial does not measure preservation of an already-open draft across code updates.

What would change this verdict: another frozen trial, with new independent
requests and fresh agents, showing more code-free successes, useful validation
through words, reliable personal scope, and no functional regressions. Passing
the existing ten after tuning specifically for them would not establish that.
