1 · The shape

Four kinds of information, four homes

Today, agents get their words from 20 texts in four kinds of place, and three of those texts are rule books that disagree. Most of the mess comes from mixing four different kinds of information. Give each kind one home, and the homes stop overlapping.

How agents behave

The Agent Book

One document in Writing, read by heading every time a message is built. You edit it like any page, and an edit counts on the next wake. Holds JEFF's soul, the one soul all residents share, the roles, the worker brief and every wake message.

What words do

Help and the dictionary

Already in the world, and written from the code, so they can't drift. Adds a dated "new since your base" list, generated from commit lines and never written by hand, so a worker knows what changed in the kernel.

Numbers and names

House settings

A world settings thing the House reads each time: worker models and reasoning, pool sizes, tools, checks, compaction, who unowned work goes to. Workers have no turn or time limit unless one is set.

What happened

Commit lines and logs

Every source commit says Source: and Missing-word:, and its body is the worker's own summary. Each worker keeps its log. These feed the "new since" list.

Each home links to the others and never copies them. Fill-ins use one form across Agora: $.card for the thing a message is about, $[[House settings]].codex_model for another thing. The code keeps one neutral fallback line per message, never a second copy of the text.

3 · Fewer source edits

The worker brief says it, landing checks it

The audit session's finding: text alone didn't hold. One worker's card told it to add to the kernel "only if a rule cannot say it", and it wrote JEFF's name into the kernel anyway. So the brief says it, and the House checks it before landing. A failed check goes back to the worker as its next turn, never as a block on its owner.

The Worker brief (draft for the Book)

Finish in this turn: build it, test it, fix what the tests
show. When unclear, make the sensible choice and say so.

First read "new since your base": what changed in the
kernel since you started.
Before making a kind or a word: run help kinds and
aspects suggest.
Before editing a file in kernel/, kernel-desktop,
agora-wm, modules or painter: read its header. It says
what may go there.
If your kernel change would name an app, person, kind or
field: stop. File the missing general word as a card,
and do the task as a marked bridge naming that card.

End with BUILD-RESULT.md. Your summary becomes the
commit's message.
From: this session (finish), kinds session (help kinds), audit session (headers, kernel rule)

What landing checks

  • Commit lines. A commit that touches source ends with Source: word|fix|seam|bridge and Missing-word: …. If either is missing, it goes back to the worker with a one-line reason.
  • The worker's own summary becomes the commit body. Today it's a card title cut short, so history can't be read from git.
  • New hard-coded names in those folders: people, dk ids, model names, English message text, app kinds inside the kernel. Each one found goes back to the worker.
  • New loose facts (aspects before and after), named for the owner. The kinds session hands over the check.
  • Commits name their files. Landing commits only its own files, so it never sweeps up another session's staged work. That happened twice today.
From: audit session (spec), kinds session (loose facts)
4 · Order

How it gets built, and by whom

  1. House settings, and a Book readerthis session

    The House reads the numbers from settings and the texts from the Book's headings each time it uses them, with one neutral fallback line in code. house.preview <agent> <moment> prints exactly what an agent would be sent.

  2. Fill the Bookdone 4 Nov; now yours to edit down

    Every text in section 2 is in the Agent Book in Writing, with today's souls as material for the two you'll write. The House switches to it once you've edited it. Old copies get superseded banners.

  3. Landing checksthis session, with the kinds session's check

    Commit lines, the worker's summary as the commit body, commits that name their files, the hard-coded-names check, the loose-facts check.

  4. "New since your base"this session

    A reading generated from the Source: and Missing-word: lines since a worker's base commit. The brief points to it.

  5. Help for kindskinds session, with you now

    A new "Kinds and parts" help topic, and one sentence in help kinds.

  6. AGENTS.mdthis session, small changes shown to you first

    Its worker-facing parts give way to a pointer to the Book. "Source edits go down over time" keeps its name, because 97 file headers cite it.

  7. Then the governorseparate design

    Once the Book has the messages, the governor's one-line nudges come from it too.
